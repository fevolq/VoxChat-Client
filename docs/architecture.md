# VoxChat Client 架构

## 分层

```text
平台界面与系统能力
        ↓
设备端应用流程（配对、选择、语音轮次）
        ↓
共享核心（认证、HTTP、NDJSON、状态模型）
        ↓
协议定义（protocol）
        ↓
VoxChat DSH 插件
```

### `protocol/`

协议是设备端与插件之间的边界，包含：

- HTTP 路径、请求和响应格式。
- 配对链接格式。
- 错误码和可恢复性提示。
- NDJSON 事件类型与顺序规则。
- 代表性请求和流式响应 fixtures。

协议文件不依赖 Android、iOS 或某一种 UI 框架。平台代码只能依赖协议定义，不能把服务端实现细节带进界面层。

### `src/core/`

共享核心只处理客户端业务，不直接调用平台 API：

- `api/`：HTTP 请求、Bearer 认证、协议类型、配对、错误和 NDJSON 帧解析。
- `turn/`：一轮语音的阶段、事件、音频块和结束状态。
- `ports.ts`：安全存储、录音、播放和扫码的系统能力接口。

共享核心不保存密钥日志，不自动重试已经提交的语音轮次，也不依赖具体 UI 状态管理库。

### `android/` 与 `ios/`

React Native 平台工程负责：

- 系统安全存储。
- 相机和二维码扫描。
- 麦克风权限、录音和音频播放。
- 网络权限、后台/前台生命周期。
- 手机与平板的响应式布局和系统导航。

手机和平板使用同一平台工程，通过尺寸和系统能力适配界面，不为平板复制一套协议或业务流程。React Native 负责共享界面和业务代码，原生目录只承载系统集成、权限和必要的高性能音频实现。

## 主要流程

### 配对

```text
扫码/输入链接
  → 校验 voxchat://pair、server、code
  → POST /pair
  → 安全存储 token
  → GET /me
  → 选择工作区和音色
```

配对成功以前，二维码中的一次性 code 不是设备凭证。配对失败不能把扫码视为成功，也不能在客户端生成或猜测新的 code。

### 语音轮次

```text
准备状态
  → 录音
  → 上传 /turns
  → 解析 phase/transcript/dsh.event/reply/speech.text
  → 接收 audio.start/audio.chunk/audio.end
  → 等待 complete
  → 播放完成或标记失败
```

每轮使用开始时的工作区、会话、模型和音色快照。客户端切换选择不会重定向已经提交的轮次。

## 状态约束

- `401`：停止使用当前 token，刷新设备状态并要求重新配对。
- `503 CONNECTION_NOT_READY`：保留本地配置，等待连接恢复后再操作。
- `409 DUPLICATE_REQUEST`：查询会话历史，不使用新 request ID 自动重发。
- 流中出现 `error` 或在 `complete` 前断开：本轮不算成功交付。
- 未知 NDJSON 事件可以记录并忽略，但必须继续校验公共 envelope 和 `seq`。
- 服务器返回的工作区、会话和音色列表是事实来源，客户端缓存只用于显示和离线过渡。

## 版本策略

`protocol/` 是客户端协议目录，当前协议版本由响应和事件中的 `protocol: 2` 表示。新增可选字段和未知事件保持向前兼容；只有无法兼容的协议变化才增加新的版本标识，并让客户端在启动时检查服务端返回的协议版本。
